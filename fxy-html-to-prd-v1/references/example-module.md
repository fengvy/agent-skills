# 示例：模块详细设计的颗粒度（项目级 PRD 第五章）

> **用途**：锚定第五章「模块详细设计」的**颗粒度、结构与标注方式**。
> **来源**：摘自一份真实 PRD（系统3 EDC 临床数据管理，由原型反推）。
> **注意**：只学结构、颗粒度、标注方式 —— **不要照搬其中的业务内容**。
> **本示例为单端项目**；多端项目的跨端关系写 PRD 第六章，不在模块内展开。
> 示例省略了 `#### 5.1 临床端` 端分节；实际 PRD 中模块挂在对应端分节下，模块标题不重复端名。

---

## A 类模块示例（有状态机 / 多分支流程 / 跨模块依赖）

### M03 临床访视计划（A 类 —— 7 态任务机、跨模块状态联动）

**1. 模块与入口**

- 所属端/页面/入口：临床端 → 导航「临床方案 → 临床访视计划」
- 功能：展示受试者任务状态；页面说明原文 `受试者入组后按临床方案自动实例化（锚点 + 偏移 + 时间窗）；事件任务随事件发生插入（无「待填写」前态，发生后即进审核）；状态收敛为 7 值…`
- **本页为只读状态视图，无任何操作列**；状态流转由 M04 审核动作或系统自动推导。

**2. 流程与规则**

- 单一路径：进入页面 → 按 项目 / 中心 / 责任人 / 编号 / 访视名称 / 状态 筛选 → 查看每行任务状态。无写操作分支。
- 筛选项：项目、中心、责任人（下拉，选项由任务数据去重生成）、编号（模糊）、访视名称（模糊）、状态（7 态）。
- 行过滤顺序：项目 → 中心 → 责任人 → 编号模糊 → 访视名模糊 → **计划日期为空则跳过（待触发不展示）** → 状态匹配。
- 权限：无角色级拦截。

**3. 状态流转**

7 态任务机（判定优先级：出组 / 冻结 → 审核态 → 逾期 → 待填写）：

| 状态 | 含义（原文） | 判定条件 |
| --- | --- | --- |
| 待填写 | 未提交采集 | 默认态，且非出组 / 冻结 / 审核态 / 逾期 |
| 待审核 | 已提交 · 一审待审 | 任务状态 = 待审核 |
| 待复核 | 一审已过 · 二审待复核 | 任务状态 = 待复核 |
| 已通过 | 审核通过 | 任务状态 = 已通过 |
| 异常 | 被驳回 · 退回修改 | 任务状态 = 已驳回（**同一底层状态在 M04 显示为「已驳回」**） |
| 已逾期 | 超过计划日期 + 时间窗未填写 | `(计划日期 + 时间窗) < 今天` 且未提交 |
| 作废 | 已出组未提交 / 周期被终止事件不再执行 | 受试者已出组且未开始 / 待填写；或周期项被冻结且未开始 / 待填写 |

**4. 异常与降级**

- 锚点未录入：计划日期为空 → **该行不展示**（页脚说明 `（待触发——锚点未录入——不展示）`）。注意原型同处还写了紫色「待触发」标签，但被前置跳过逻辑覆盖，**该标签实际不可达** —— 已列入待确认清单。
- 原型未体现加载态、网络 / 服务错误态。

**5. 字段定义**

| 字段名(英文) | 字段中文名 | 类型/取值 | 必填/默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `project` | 项目 | 文本 | — | 筛选项，来自任务数据去重 |
| `center` | 中心 | 文本 | — | 筛选项，来自任务数据去重 |
| `owner` | 责任人 | 文本 | — | 筛选项，来自任务数据去重 |
| `code` | 编号 | 文本 | — | 模糊匹配 |
| `visitName` | 访视名称 | 文本 | — | 模糊匹配 |
| `planDate` | 计划日期 | 日期 `YYYY-MM-DD` | —（由锚点 + 偏移推导） | 锚点日期 + 偏移；为空则整行不展示 |
| `status` | 状态 | 枚举：待填写 / 待审核 / 待复核 / 已通过 / 异常 / 已逾期 / 作废 | — | 页面展示态，由底层 `taskStatus` 映射 |
| `taskStatus` | 任务状态（隐藏） | 枚举：未开始 / 待填写 / 待审核 / 待复核 / 已通过 / 已驳回 | — | 底层状态；与 `status` 的映射见状态表 |

> 本表只写业务可确认的取值与约束，不展开机器级实现细节。

## B 类模块示例（纯展示 / 单步操作 / 无状态流转）

### M09 审计日志（B 类 —— 静态展示，检索未实现）

**1. 模块与入口**

- 所属端/页面/入口：临床端 → 导航「审计日志」
- 功能：静态展示操作留痕；副标题原文 `全后台操作留痕，可检索`。

**2. 流程与规则**

- 进入即渲染日志表；**无导出、无详情查看**。
- 筛选栏含 操作人 / 关键字、模块、操作类型、日期、「查询」，但**无事件绑定，检索未实现**。
- 列表列：时间 / 操作人 / 模块 / 操作类型 / 操作内容 / 结果。

**3. 字段定义**

| 字段名(英文) | 字段中文名 | 类型/取值 | 必填/默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `time` | 时间 | 文本 `YYYY-MM-DD HH:mm` | — | 展示 |
| `operator` | 操作人 | 文本 | — | 展示 |
| `module` | 模块 | 文本（原型未给出枚举） | — | 筛选控件未接线 |
| `type` | 操作类型 | 枚举：发布 / 配置 / 创建 / 审核 / 编辑 | — | 筛选控件未接线 |
| `content` | 操作内容 | 文本 | — | 展示 |
| `result` | 结果 | 文本（原型未给出枚举） | — | 展示 |

> B 类到这里就结束 —— **没有「状态流转」「异常与降级」小节**（无有状态对象、无失败路径，整节省略，不写「不适用」）。

## 颗粒度对照速查

| 维度 | A 类 | B 类 |
| --- | --- | --- |
| 小节 | 模块与入口、流程与规则、状态流转、异常与降级、字段表 | 模块与入口、流程与规则、字段表；有失败路径再补异常 |
| 篇幅 | 约 1 屏（不含字段表） | 约半屏 |
| 超出时 | 先判断「复述」还是「信息密度」：复述则删，密度高则拆子模块（M02a / M02b） | — |
| 异常文案 | 逐条给原文 | 无异常路径则不写 |

## 两个高频易错点（本例中真实出现过）

1. **同一底层数据在不同模块显示为不同名称**（本例 `已驳回` 在计划页显示为「异常」）→ 必须显式写出映射关系，否则读者会误以为是两个独立状态。
2. **原型写了标签但代码不可达**（本例「待触发」紫标被前置 `continue` 覆盖）→ 这类矛盾要同时写清「原型写了什么」与「实际行为是什么」，并进待确认清单，不可只写其中一个。
