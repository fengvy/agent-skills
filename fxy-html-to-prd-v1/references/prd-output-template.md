# 输出模板：结构化 PRD（九章）

> 章节骨架。标注规则、撰写铁律、篇幅纪律统一见 `SKILL.md`（标注三级：直接观察→【已确认】；隐含推断→【推断】须写依据；无法确定→【待确认】进第九章）。

---

### 一、文档信息

- 产品名称、版本号、撰写日期、作者
- 文档状态（草稿/评审中/已确认）
- 变更记录（版本、日期、变更内容、变更人）

### 二、产品概述

- 产品定位与核心价值（一句话）
- 目标用户与典型使用场景
- 业务目标与成功指标（可量化）
- 名词解释：**只收原型中真实出现的专有术语**，不要为凑数补通用词

### 三、信息架构与页面清单

- 全局页面清单（页面名称、入口、所属模块）
- 页面间跳转关系（从哪页可跳到哪页，触发条件）
- 多页面原型先输出整体信息架构，再逐模块展开

### 四、全局影响范围

只写**跨模块共性影响**（单模块自身影响在第五章，模块间依赖在第六章）。**有实质内容的维度才列，无则整项不出现**（不要写"无影响"占位）：

1. **业务流程**：环节/角色、对现有流程的改变点
2. **用户体验**：路径变化、学习成本、信息架构调整
3. **权限与安全**：敏感数据、越权风险、操作留痕
4. **数据**：新增采集、历史数据处理、口径变更
5. **合规与隐私**：个人信息收集、用户协议、数据使用范围

### 五、模块详细设计

对原型中每个可识别的功能模块逐一展开。**先判定 A/B 类**（判定标准见 SKILL.md 篇幅纪律）：

- **A 类（复杂模块）**：有状态机 / 多分支流程 / 跨模块数据依赖 → 按下述全部适用项展开
- **B 类（简单模块）**：纯展示 / 单步操作 / 无状态流转 → 只写第 1、2、3、7 项（功能描述、操作流程、交互规则、字段表）；有数据加载或提交动作时补第 6 项（异常与降级）；其余省略

**不适用的小节不要出现**（见 SKILL.md 篇幅纪律 3）。

#### M0X 模块名称（A 类 / B 类 —— 判定理由一句话）

1. **模块基本信息**
   - 所属页面 / 入口位置
   - 功能描述（该模块做什么，解决什么问题）
2. **用户操作流程**
   - 入口 → 操作 → 反馈 → 结果，步骤列表描述
   - 多条分支分别列出
3. **交互规则与边界条件**
   - 正常态、加载态、空态、错误态分别如何展示
   - 输入校验规则（必填、格式、长度、范围）
   - 按钮可用/禁用条件
   - 权限控制（谁可见、谁可操作）
4. **数据来源与依赖**
   - 数据项名称
   - 来源类型（系统已有数据 / 用户填写录入 / 第三方业务数据 / 运营配置 / 系统自动生成）
   - 更新时机（页面进入时 / 用户操作触发后 / 定期更新 / 实时同步）
   - 依赖关系（依赖哪些前置数据或业务条件）
5. **状态流转**（不涉及有状态对象时整节省略）
   - 有状态对象名称
   - 全部状态列表及含义
   - 流转触发条件（什么操作或事件导致状态变更）
   - 流转路径（文字描述从 A 状态到 B 状态的完整路径）
   - 各状态下的允许操作与禁止操作
6. **异常与降级策略**
   - 数据加载失败：重试 / 展示默认值 / 阻断操作？用户看到什么提示？
   - 依赖数据缺失：如何展示？是否允许继续操作？
   - 操作执行失败：什么反馈？是否支持重试？数据是否回滚？
   - 极端场景（数据量超大、并发操作）的业务降级方案
7. **本模块字段定义**

   仅列展示字段、输入字段、隐藏字段中**实际存在**的数据项：

   | 字段名(英文) | 字段中文名 | 类型/长度格式 | 必填/默认值 | 取值范围/枚举 | 来源 | 说明 |
   |---|---|---|---|---|---|---|

   要求：枚举列全部可选值及含义、金额标单位与精度、时间标格式、UI 反推字段标"推断自界面"（细则见 SKILL.md 铁律 5）；配置驱动的动态表单字段不逐条固化，改写「字段来源与渲染/录入口径」（铁律 2）；引用其他系统字段的收录范围见铁律 3。

### 六、模块间依赖关系总表

**全文唯一写依赖关系的地方**（第五章不重复）：

1. **模块依赖矩阵**：被依赖方 → 依赖方 → 依赖内容
2. **数据流转关系**：关键数据在哪些模块之间流转，方向是什么
3. **模块执行顺序**：是否存在必须先完成 A 才能使用 B 的先后约束

### 七、全局字段总表（索引）

> 字段属性的权威定义在第五章各模块内，**此处不重复列属性**，只做全局检索入口——避免同一批字段被抄两遍。

- 表格：`字段名(英文) | 字段中文名 | 出现模块`（一个字段出现在多个模块时合并为一行，模块用逗号分隔）
- 如无跨模块复用的字段，本章可只保留一句"字段定义见第五章各模块，无跨模块复用字段"

### 八、非功能需求

**仅写有证据支撑的项；无依据的项不要为凑齐栏目硬编。**

覆盖方向：性能体验、兼容性（浏览器/分辨率/设备）、可用性（无障碍/多语言/暗色模式）、数据量级预估。

### 九、待确认问题清单

反向推导中无法从原型确定、需业务方确认的问题，每条标注：

- 问题描述
- 影响的模块/字段
- 建议方案（如有）
- 优先级（高/中/低）
